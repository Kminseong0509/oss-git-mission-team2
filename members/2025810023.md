### 내가 review한 Pull Request
- #7 README에 저장소 구조 설명 추가 PR을 확인하고 comment를 남겼다.

### 내가 겪은 오류 또는 실수
- main branch에서 직접 docs/conflict-log.md를 수정한 적이 있었다.
- PR을 만들려고 했을 때 main과 branch가 동일하다는 메시지가 나타났다.
- 원인은 수정 commit이 PR용 branch에 제대로 분리되지 않았기 때문이었다.

### 해결 방법
- main에서 직접 작업하지 않고 새 branch를 만들어 작업해야 한다는 점을 확인했다.
- 이후 docs/week3-conflict-log-final branch를 새로 만들어 conflict-log.md 작업을 정리했다.

### 6월 시험 대비로 기억할 점
- 작업 전에는 항상 `git checkout main` 후 `git pull origin main --no-rebase`를 실행한다.
- 새 작업은 main이 아니라 개인 branch에서 진행한다.
- `git status`는 현재 branch, 수정 파일, commit 가능 여부를 확인하는 가장 기본 명령어다.
- PR을 만들려면 main과 비교 branch 사이에 차이가 있어야 한다.
- conflict가 발생하면 conflict marker를 지우고 최종 내용을 사람이 직접 결정해야 한다.
